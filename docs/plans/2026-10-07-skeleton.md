# Infrastructure Skeleton Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build a locally validated v0.0.1 skeleton, then prove cloud apply/destroy and CI before release.

**Architecture:** Separate local-state bootstrap from the S3-state demo stack. CI validates PRs offline and uses an exact main OIDC subject for read-only cloud plans. The account budget restricts project producer input at 100%; it does not stop running services.

**Tech Stack:** Terraform >=1.10, AWS provider 6.x, S3, Kinesis, Glue, IAM, Budgets, CloudWatch, GitHub Actions.

---

## Decisions

Proceed with the documented stage order: skeleton → streaming → reliability → analytics. A complete three-stage implementation now would delay the first verifiable deliverable. A local-only streaming simulation would not establish the AWS deployment evidence required by PROJECT.md.

Use an opt-in billable stream; enable it for acceptance and destroy immediately afterward. Keep bootstrap state bucket after demo teardown. Never delete state as part of nuke. Default names/tags stay identical between bootstrap and main; changing project/env requires coordinated changes to the backend key and CI.

## Task 1: Bootstrap
Files: infra/bootstrap/{main,variables}.tf and terraform.tfvars.example.
Create encrypted/versioned private state, optional shared OIDC provider, exact-sub read-only plan role. Run terraform fmt and init -backend=false / validate. Commit lockfile after provider resolution.

## Task 2: Demo resources and cost controls
Files: infra/{main,budget,variables,outputs,versions,backend}.tf and examples.
Create private encrypted lake, 7-day prefixes, catalog, opt-in encrypted stream, 3-day logs, restricted producer and Budgets roles, $30 account-wide alerts/action. Validate provider schemas. Do not claim the action shuts down resources.

## Task 3: CI and operational commands
Files: .github/workflows/ci.yml, Makefile, .gitignore.
PR secret scan/fmt/validate needs no AWS. Main/manual read-only plan uses OIDC and encrypted state locks. No apply job. make apply consumes a reviewed local saved plan; make destroy prompts; make nuke requires typing the lake bucket.
Run make check, make -n plan/apply/destroy/nuke and a redacted secret scan. Check tracked state after Git initialization.

## Task 4: Documentation and evidence
Files: README.md, docs/architecture.md, docs/runbook.md, docs/acceptance.md.
Include truthful roadmap, diagram, reproducible steps, IAM boundaries, budget delay and resource teardown. Record local checks separately from AWS/CI evidence. Do not mark v0.0.1 accepted until enable_stream=true apply/destroy, CI and resource inventory have evidence.

## Task 5: Account-specific acceptance (requires user configuration)
Supply GitHub repo/OIDC subject, AWS account/region, existing operator role and budget email. Run aws sts get-caller-identity, bootstrap plan/apply, fill backend file, main plan/apply. Capture resource inventory and budget action. Run main CI plan and PR checks. Destroy stream/lake/catalog/logs/roles/budget; retain documented bootstrap state/OIDC role. Publish release only when checklist passes.

## Later phases

v0.2: event-time deduplication, schema drift fixtures, DLQ, checkpoint failure/recovery evidence.
v1.0: start Snowflake trial just before work; Airflow, dbt facts/marts/SCD2, RBAC and cost evidence.
